#+TITLE: org-table-fit

Fit Org tables to the window width, destructively or as
non-destructive overlays.

* Overview
~org-table-fit~ wraps wide Org tables so they fit the window.  It offers two ways to work:

- Destructive fit :: ~org-table-fit-window~ rewrites the table at point into wrapped continuation rows; ~org-table-fit-unwrap~ restores the original single-line rows.  Wrapped state is tracked with text properties, so refitting a wrapped table merges its continuation rows first.
- Overlay display :: ~org-table-fit-overlay-mode~ (inspired by [[https://github.com/yibie/org-table-widget][org-table-widget]]) covers each source line of wide tables with an overlay holding its wrapped rendering.  The buffer text is never modified, so export, formulas and Babel keep seeing the original table.  Moving point into a table reveals its source for ordinary editing; moving out lays it out again.  With revealing disabled ((setq org-table-fit-overlay-reveal-on-point nil)), point can still traverse the table and the cursor follows the rendered rows.

Wrapping reuses one pipeline in both paths: natural/minimum column widths, proportional shrinking to the target width, and continuation-row merging.  Formula cells such as ~=1+2= and verbatim spans such as ~=C-x C-s=~ are never broken.

* Requirements
- Emacs 29.1+
- Org mode (built in)

No other dependencies.  The overlay display works in terminal frames as well as GUI frames.

* Installation
Clone the repository and add it to your ~load-path~:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/org-table-fit")
(require 'org-table-fit)
#+end_src

With ~use-package~ (enables the overlay display in Org buffers,
keeps tables traversable by default, ~C-c t r~ toggles editing):

#+begin_src emacs-lisp
(use-package org-table-fit
  :load-path "~/.emacs.d/offline-packages/local-packages/org-table-fit"
  :demand t
  :hook (org-mode . org-table-fit-overlay-mode)
  :bind (:map org-mode-map
              ("C-c t i" . org-table-fit-window)
              ("C-c t t" . org-table-fit-overlay-mode)
              ("C-c t u" . org-table-fit-unwrap)
              ("C-c t r" . org-table-fit-toggle-reveal-on-point))
  :config
  (setq org-table-fit-overlay-reveal-on-point nil))
#+end_src

* Usage
** Fit the table at point (destructive)
#+begin_src emacs-lisp
M-x org-table-fit-window    ;; wrap table at point to the window width
M-x org-table-fit-unwrap    ;; restore single-line rows
#+end_src

With a numeric prefix argument, ~org-table-fit-window~ fits to that many columns instead, e.g. ~C-u 60 M-x org-table-fit-window~.

~M-x org-table-fit-mode~ enables a buffer-local mode that automatically refits the table at point when the window size changes.

** Display tables as overlays (non-destructive)
#+begin_src emacs-lisp
M-x org-table-fit-overlay-mode   ;; show all wide tables as overlays
M-x org-table-fit-display-table  ;; overlay just the table at point
M-x org-table-fit-hide-table     ;; reveal the source of the table at point
M-x org-table-fit-toggle-display ;; toggle the overlay at point
M-x org-table-fit-toggle-reveal-on-point ;; toggle editing vs. traversing
M-x org-table-fit-next-row ;; step down one source row, stay on column 0
M-x org-table-fit-prev-row ;; step up one source row, stay on column 0
M-x org-table-fit-refresh-overlays
#+end_src

The row-stepping commands move by buffer lines (never skipping
across a rendering) and never reveal the source.  While the overlay
mode is on, the usual line motion keys do the context-sensitive
thing automatically: ~C-n~ / ~C-p~ (and the arrow keys) step row by
row with the cursor locked to the first column inside displayed
tables, and behave exactly as before everywhere else.  Line motion
that enters a displayed table lands on the first (from above) or
last (from below) source row's start, so point stays at the left
edge instead of snapping to the row end.

Tables that already fit need no overlay and are left as editable source.

* Customization
~M-x customize-group RET org-table-fit RET~.  The main options:

- ~org-table-fit-width-fraction~ (default ~0.95~): fraction of the window body width used as the fit target by both paths.
- ~org-table-fit-min-column-width~ (default ~1~): floor for column widths when the table cannot fit otherwise.
- ~org-table-fit-overlay-reveal-on-point~ (default ~t~): show a table's source while point is inside it.
- ~org-table-fit-overlay-relayout-delay~ (default ~0.15~): idle seconds before redisplaying overlays after resizes or edits; zero or less means immediately.

* Relation to org-table-widget
The overlay display borrows its model from ~org-table-widget~: ~display ""~ + ~before-string~ overlays, reveal-on-point (including the upward-entry cursor correction), debounced relayout, and modification hooks.  Unlike that package there is no TextUI dependency.  Layout is character-cell based; on graphical frames the fit target is measured from the font actually used to display the table (a two-character ~window-text-pixel-size~ probe whose difference cancels per-line display decorations such as line-number gutters), so a table face that does not scale with the default face is still fitted correctly.  See [[file:CHANGELOG.org][CHANGELOG.org]] for details.

* Contributing
The implementation lives in ~org-table-fit.el~; the regression suite in ~test/org-table-fit-test.el~.  Run the suite with:

#+begin_src shell
emacs -Q --batch -L . -l test/org-table-fit-test.el
#+end_src

It exits nonzero on failure; the pass condition is ~0 failure(s)~.  When changing wrapping, row merging, width allocation, or rendering, extend the suite to cover the behavior.
