#+TITLE: org-table-fit Changelog

* Unreleased
** Added
- Non-destructive overlay display inspired by ~org-table-widget~.  New commands ~org-table-fit-display-table~, ~org-table-fit-hide-table~, ~org-table-fit-toggle-display~ and ~org-table-fit-refresh-overlays~ cover wide tables with per-line overlays (~display ""~ + ~before-string~) so the buffer text stays intact for export, formulas and Babel.
- New buffer-local minor mode ~org-table-fit-overlay-mode~.  It lays out every wide table as overlays, reveals a table's source while point is inside it (including the upward-entry cursor correction), and redisplays after edits, window resizing and text scaling.
- Each row overlay carries an integer ~cursor~ property, so with ~org-table-fit-overlay-reveal-on-point~ set to nil point can still traverse the table and the cursor follows the   matching rendered row.  Line motion that would skip across a
  displayed table steps into it instead, and every line-motion
  landing inside a displayed table goes to the start of the line so
  the cursor never drifts to the row end.
- New options ~org-table-fit-overlay-reveal-on-point~ (default ~t~) and ~org-table-fit-overlay-relayout-delay~ (default ~0.15~).
- New command ~org-table-fit-toggle-reveal-on-point~ flipping reveal
  on point (editing tables) versus traversing the rendering.
  Suggested ~org-mode-map~ keys: ~C-c t i~/~C-c t f~ fit,
  ~C-c t t~ toggles the overlay mode, ~C-c t u~ unwraps,
  ~C-c t r~ toggles reveal on point.
- New commands ~org-table-fit-next-row~ and ~org-table-fit-prev-row~
  stepping one source row at a time by buffer lines.  They always
  land at the start of the line and never reveal the source, so the
  cursor stays locked to the first rendered column while traversing.
  While the overlay mode is on, ~C-n~ / ~C-p~ (and arrow keys) remap
  to context-sensitive variants that step rows inside displayed
  tables and behave normally everywhere else.  Row detection is by
  line, so the remapped keys engage from any column of a hidden row,
  not just column 0.
- Narrow tables need no overlay and are left as editable source.
** Fixed
- Fit widths are now measured in characters of the remapped default face (~window-body-width~ with ~remap~).  Changing the font scale with ~text-scale-mode~ now reflows both destructive fits and display overlays instead of leaving them wider than the window.
- ~org-table-fit-mode~ also refits on ~text-scale-mode-hook~, so destructive fits follow font scale changes as well.
- Row navigation through a displayed table no longer snaps point/cursor to the right edge.  Redisplay treats the overlays' empty ~display~ property as intangible and pushed point out of the hidden source; landings now set ~disable-point-adjustment~ so the cursor stays on the rendered row's left edge.
- Line motion entering a displayed table now lands on the boundary row's start (first row from above, last from below), matching the existing upward-entry correction and the row-stepping commands.
** Changed
- Refactored ~org-table-fit-window~ onto shared planning helpers (~org-table-fit--target-width~, ~org-table-fit--logical-rows~, ~org-table-fit--column-count~, ~org-table-fit--natural-minimum-widths~, ~org-table-fit--wrap-all-rows~) used by both the destructive and the overlay paths.  Wrapping behavior is unchanged.
- Destructive refit (~org-table-fit-window~) and unwrap (~org-table-fit-unwrap~) now clear stale display overlays in the replaced region.

* Version 0.1.4
- Destructive fit via ~org-table-fit-window~ with proportional width allocation and ~org-table-fit-unwrap~ restoring single-line rows.
- Verbatim markup spans (~=...=~, ~ ~...~ ~, links) are kept intact while wrapping; formula cells (~=1+2~) are never wrapped.
- Continuation rows are tracked with text properties so refit and unwrap recover exact rows.
- Buffer-local ~org-table-fit-mode~ refits the table at point on window size changes.
